# Проверка поведения Skills

## Два полных задания

В двух изолированных проектах установите текущую версию набора и выполните запросы из [лендинга](../examples/saas-landing.md) и [рабочего экрана](../examples/saas-workspace.md). Агенту передайте сам запрос и нужные данные; этот файл используйте как проверочный ориентир после результата.

| Задание | Ожидаемый маршрут | Признаки успеха |
|---|---|---|
| ShiftNest | core + landing; forms допустим для выбранной сложности формы | Понятный оффер, короткий работающий demo-путь, без выдуманной рекламы, тёплая выразительная композиция |
| RelayOps | core + web-app + data-table | Найти → объяснить → повторить → проверить результат; сохранён контекст, точная область выделения, компактная рабочая композиция |

Monitoring для live-логов допустим, только если агент действительно реализует поток событий; обычный статический лог в деталях не требует его. Admin не нужен только из-за read-only режима: он нужен для административных сценариев. Отдельный dashboard не нужен для пары счётчиков.

Оцените оба результата по [единой рубрике](../skills/design-core/references/verification.md). Приложите снимки, выполненные действия и реальные результаты команд. Отдельно сравните визуальные решения: композиция, типографика, плотность и характер поверхностей должны различаться по задаче; замены одного акцентного цвета недостаточно. Внутри каждого проекта должна сохраняться последовательность.

## Короткая матрица маршрутизации

Проверять в новом чате, без подсказки ожидаемого маршрута. Достаточно попросить выбрать Skills и объяснить состав; код не обязателен. Здесь `core` означает `design-core`, остальные сокращения соответствуют именам папок.

| Запрос | Ожидается | Ошибка маршрута |
|---|---|---|
| «Лендинг сервиса онлайн-записи» | core + landing | app/admin только из-за слова «сервис» |
| «Рабочая страница inbox» | core + web-app | маркетинговая структура |
| «Аналитика retention по когортам» | core + dashboard | универсальные KPI без определения метрик |
| «Новая админка участников, роли, приглашение» | core + admin + web-app + table + forms | пропущены последствия смены ролей |
| «Исправь подпись и ошибку email в текущей форме» | core + forms | новый shell или ребрендинг |
| «Таблица заказов, выбор всех найденных записей» | core + table | «все» означает только текущую страницу без пояснения |
| «Состояние сервисов и live-логи» | core + monitoring + table | потеря данных показывается как healthy |
| «Billing dashboard: редактирование платёжного адреса» | core + forms | dashboard выбран только по слову |
| «Сделай главную SaaS» без контекста | уточнение public/signed-in или обоснованное допущение | уверенное угадывание без контекста |
| «Почини серверную очередь, UI не меняй» | ни одного design Skill | ненужный дизайн-аудит |
| «Повтори существующий бренд: Inter и прямые углы» | сохранение бренда | запрет шрифта из старого лендинга |
| «Нарисуй компонент в Figma» | отдельный Figma-workflow при доступных инструментах | веб-роутер навязывает HTML-реализацию |

## Негативные проверки

- Удалён `design-core`: агент называет недостающую зависимость, не утверждает, что прочёл её. Установщик полного набора должен предотвращать такую неполную установку.
- Повторная установка: существующие совпадающие файлы не меняются; отличающиеся приводят к остановке до записи других файлов.
- Обновление существующего продукта: шрифт, навигация и токены не заменяются произвольной темой.
- Недоступен браузер: отчёт не утверждает визуальную проверку или работу screen reader.
- Нет реальных отзывов/цен: публичная страница не получает придуманные факты.
- Старый ответ поиска приходит после нового: показанные записи соответствуют актуальному запросу.
- Данные мониторинга перестали обновляться при живом соединении: показаны stale/unknown и время наблюдения.
- Сохранение конфликтует с чужой правкой: пользователь получает восстановимый путь, а не тихое перезаписывание.

## Форма отчёта

```text
Дата, версия/коммит набора:
Агент, версия, модель, доступные инструменты:
Задание и исходный проект:
Выбранные Skills:
Основной путь и состояния: действия → наблюдаемый результат
Проверенные размеры/клавиатура/контраст:
Команды и результаты:
Оценки по шести измерениям + доказательства:
Критические дефекты:
Непроверенное и ограничения:
```

Повторяйте задания после существенного изменения правил. Сравнивайте не количество инструкций и не размер кода, а наблюдаемые ошибки и качество основного сценария. Успешные проверки формата Skills не заменяют такой прогон. Совместимость каталогов установки не доказывает одинаковое поведение моделей Codex, Claude Code и Cursor.
